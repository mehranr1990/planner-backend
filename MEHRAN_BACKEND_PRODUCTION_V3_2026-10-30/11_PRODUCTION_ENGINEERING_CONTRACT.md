# Mehran — Production-grade backend engineering contract / release invariants

**Contract type:** proposed engineering acceptance framework, not source-code proof and not authorization to implement. Apply to Phase 2–7 and every shared subsystem.

## 1. Shared custody and schema gate (P2-01 — hard block)
Repository analysis must list ALL ownership, tenant and deletion paths including `Space`, `ownerUserId`, tenant polymorphism, Task/Goal/Calendar/Files/Finance, auth session, jobs, sync, counters, exports, indexes, FK target actions, composite keys, unique constraints and query filters. Present two feasible target shapes with pros/cons: type-discriminated custody under Space versus Personal Space kept distinct with a new SharedBoundary; choose only after actual FK inventory. Preserve mandatory personal ownership; never set owner nullable as a shortcut; never use fake system User. Define custody state and exclusive owner/member invariants. New multi-context refs must carry explicit scope IDs and enforce typed relational integrity. Existing personal endpoints preserve behavior. Plan expand -> dual-compat/read -> backfill -> verify -> constrain -> retire; produce per-migration forward/rollback, lock timing, data snapshots and rescue of interrupted backfills. Dry-run with realistic populated P1 data and historical migration checksum comparison.

## 2. Authorization contract (P2-01/02 — hard block)
For every command/query: identify resource owner module, actor and account state, scope/custodian, membership/grant revision, action capability, resource visibility, response shape, and DB transaction boundary. Write matrix rows at minimum: invite/create/list/get/update/delete/archive/restore/transfer/export/search/aggregate/file download/approve/revoke/membership change. Actor classes: owner, admin, manager, lead, member, viewer, verified grant-only guest, invited-not-member, other-space member, suspended, revoked, deleted. Tests must prove cross-tenant resource IDs, child-resource mismatches, search/count leak, file keys/URLs, indirect projections, exports, notification payloads, rehydrated jobs, stale websockets and queued operations remain inaccessible. No cache-only authorization at a write commit. Define and stress-test deterministic lock order and version-fencing around revoke + write + owner transfer. Database constraints must prevent membership/custody corruption under concurrency.

## 3. Exit, erasure and retention contract (P2, then each new domain)
Separate personal erasure, membership departure, removal of a user's sensitive profile, shared-authored content retention, and entity/workspace dissolution. Model an owner-transfer/closure workflow for sole-custodian deletion without indefinitely holding personal data hostage. Define retained content pseudonymization and separate linkage mapping; prohibit exposing former author through search, analytics, notification and export when erased. Handle payment/HR/legal preservation only under established applicable obligations. Include queued job cancellation, exports and sync cursors invalidation, derivative-file deletion, restore replay fencing, log/backup retention exception register, and verified recovery tests after backup restore.

## 4. Durable state and concurrency
All business writes have clearly scoped idempotency key, DB uniqueness or conflict detection, and outbox delivery. State machines must refuse invalid transitions and document retry behavior. Assignments, approval decisions, project transfers and social expense corrections require stable snapshots; API must distinguish 401/403/404 according to leak policy, 409 conflict and 422 invalid data. No external side effects inside database transactions; workers must safely retry with bounded backoff, poison queue/dead-letter handling and observability. Soft deletion is not a legal erase by itself.

## 5. API and consumers
Each batch creates a *proposed* operation contract BEFORE implementation, with method/path, request/response Zod, actor/capability, tenancy, pagination, idempotency, revision/ETag, errors, rate/size limits and examples for locale/timezone/money. Then generate OpenAPI from actual implemented routes, validate schema and diff against baseline, run compiled HTTP smoke, and provide a reproducible OpenAPI JSON artifact for frontend agent. Future endpoints must never be included as real implemented endpoints. Use stable opaque identifiers and external reference guards; avoid new API version without breaking-change proposal. Validate Better Auth cookies, CORS, CSRF, origin and session rotation in real HTTP settings.

## 6. Messaging and media (P5/P6)
Messages persist with per-conversation monotonic ordering and unique client-send idempotency keys. PostgreSQL commits and outbox own truth; WebSocket transports hints, never sole durability. Reconnect returns bounded authorized REST catch-up; upon revocation, all membership-sensitive subscriptions and paginated reads reject stale credentials. For scale beyond one instance, define delivery fanout and presence topology before claiming multi-node readiness. Rate-limit and bound text, mentions, attachments, search and typing signals. **Owner-approved:** edit <=48h; author delete-for-everyone <=48h for DM/private groups, policy-controlled for work channels; after 48h ordinary author delete-for-self only. Enforce server-side using committed message timestamp and permission recheck.** Define separate moderation/legal redaction. Do not promise instant backup purge.
Media ingest must stream to quarantine, enforce original byte limit and safe content sniffing, limit pixel counts/decompression bombs, malware checks, stripping unsafe metadata (especially photo geolocation), bounded worker CPU/time, and private access to source + derivatives. Don't trust MIME, extension or audio duration supplied by client. Track orphan cleanup and quotas atomically, including upload reservation, expired pending objects, replacements and deletion; enforce independent hard security ceilings even when Admin raises plan quotas.

## 7. Finance consistency (P4/P6)
Business money uses exact decimal/minor units and explicit currency; no floating-point rounding or cross-currency addition without dated FX source. Company expense claims, allocations, approvals, budget reservations, reimbursements, partial paid acknowledgements, refunds/reversals and disputes are different records/state machines. No recorded reimbursement equals actual payment rail. Social expense proposal is never effective until approved; approver correction creates new revision, previous approved remains effective until the next approved. Settled balances change only through traceable adjustment entries, not silent historical mutation. Reconcile sums of shares to approved amounts with deterministic rounding and safe concurrency; personal finance posting is explicit opt-in, idempotent and independently owned.

## 8. Entitlement and admin without premature billing
From P2 onwards each resource creator records stable entitlement/usage subject, quota kind, delta/reservation and authoritative write enforcement seam; **current commercial enforcement disabled** for all published features. Security size/rate/abuse ceilings remain on. P7 resolves versioned feature keys, plan entitlements, workspace fixed-price/seat bands, usage meters, grants and effective dates with audited policy changes. Serialise quota checks and reservations in DB to prevent over-allocation once active; support rollback, downgrade/grace and read/export of existing data. No frontend-only quotas, no external charge, tax assumption or customer billing until explicit separate activation.

## 9. Security, observability and operations
Require threat models and security test coverage for every new tenant boundary. Record audit events for membership, exports, privileged access, approvals and admin exceptions while redacting secrets, HR confidential data, message bodies and tokens. Document backup encryption/key rotation, off-host durable backups, monthly test restores (proposed cadence — confirm with operations), region-specific retention, restricted operator access, alert runbooks and incident ownership. Admin user metadata access does not imply message/journal/HR content access. MFA for platform administrators is mandatory when admin exists; verify actual provider support instead of asserting.

## 10. Measurable go/no-go evidence before customer rollout
Owners must explicitly approve: initial workload/capacity profile; p95/p99 latency and error budgets per endpoint type; acceptable availability; RPO/RTO; backup storage and restore drill frequency; log retention and alerting; and jurisdiction-specific legal review for HR/finances/communication. Produce environment topology, performance and soak results, DB query-plan index inventory, concurrency collision tests, scripted restore proving Erasure/Revocation invariants, TLS/origin/CSRF/auth/recovery runbook, CI checks, dependency/secret scan, and rollback rehearsal. Values cannot be claimed without measurement. Feature completion alone is NEVER launch clearance.
