# Phase 2–7 Backend Specification — Approved Product Scope / Proposed Engineering Boundaries

The following are **backend behavioral requirements**, not invented routes or table names. The implementation agent must inspect actual contracts and create an owner-reviewed ADR for changes to source owner semantics. All future APIs MUST be generated/tested through the established Zod/OpenAPI pattern, preserve `/api/v1/me` semantics, and require server-side authorization.

## Phase 2 — Projects + collaborative access (first critical infrastructure)
**Boundary model:** personal Space intact; new typed shared data custody with roles/relations and transactional membership fence. A Project may be independent or attached to an authorized Team/Company. Attachment/association is not automatic custodial transfer. Support creator, effective custodian, manager, member, guest grant and assignee separately. A project has Phases, Sections and Milestones; nested Subprojects excluded. Core project lifecycle creation/update/archive/restore/controlled deletion. Confirm last-custodian transfer and retention before implementation.

**Tasks and Goals:** existing unified owners expose typed, permission-aware commands; no second Task/Goal engine. Primary assignee + contributors, Pending/Accepted/Declined acceptance independent of lifecycle Task status; reasoned decline and audited reassignment. Organization policy may require assignment acceptance automatically only under approved restrictive rule. Display accepted assigned work in personal authorized projections with selectable calendar overlays; private TimeBlock optional by user preference and no copying of sensitive project contents. Task/Goal associations and typed references must not break same-Space FK invariants or personal erasure.

**Workflow:** published versioned definitions and scoped custom statuses; transition rules and authorization checked on every write. Changing workflow does not silently rewrite existing task state. Dependencies FS/SS/FF/SF with lag/lead and cycle rejection; never reschedule chain automatically without explicit preview/approval. Custom fields text, numeric, date, boolean, single/multiple select, person, currency; typed validation/defaults/versions/limits/search and secure deprecation. Templates, bulk and CSV import have bounded dry-run/validation/idempotent commit or clear rollback policy.

**Collaboration:** project role matrix Owner/Admin/Manager/Member/Viewer, verified-account invitations and narrow grants. Project-scoped files/comments/audit and risk/issue register (severity, probability, owner, mitigation, history). Estimates, recorded project-work time, capacity, workload, delays, report snapshots and projections for List/Kanban/Calendar/Timeline/Gantt/Dashboard. Backend supplies consistent data for views, not separate view databases.

**Acceptance examples:** outsider cannot discover IDs/counts/files; member denied expired/revoked grant; concurrent revoke+write serializes correctly; independent project owned by user without team; accepting task displays authorized personal reference without ownership copy; mandatory organizational assignment recorded with policy; project archive preserves recoverability; linked task status/workflow revision preserves history; cycle rejected; transfer preview excludes private notes; 24 historical migrations unchanged.

## Phase 3 — Teams
Team independent or attached to Company; approved multi-company/multi-team membership. Roles Owner/Admin/Lead/Member/Viewer. Per-Project explicit access; no automatic full Project access just by joining a Team. Verified non-team collaborator may receive narrow Project access. Team can own direct Tasks/Goals and Calendar using same engines, plus Project references, group planning and member availability. Weekly planning, optional Sprint/Backlog/Review, work capacity and portfolio dashboards, safe aggregated measures. Team meeting basics: event/invite/agenda (full meeting workflows Phase 5).

Performance: transparent task/work KPIs with clear source/denominator. Recognition private/public as allowed; corrective actions reason, evidence, response/appeal, default confidential, explicit review/audit for bounded disclosure. No covert scoring or automatic pay deduction. Transfer member between teams must reconcile assignments and keep original shared source ownership; independent Team joining Company requires custody/privacy preview and approvals. Archive/restore/termination handles projects, files, grants and last owner.

**Acceptance examples:** same person different roles in two teams; team membership insufficient to read unrelated Project; team dashboard never includes private mood/finances; manager views project work time but not personal Focus history; recognition visibility scoped; blocked team departure leaves no active grant; team-to-company attachment doesn't bulk reveal past secrets.

## Phase 4 — Companies
Organization with one shared custody boundary and internal Department/Unit/Team contexts under independently authorized per-resource grants. Multiple independent companies per account; roles Owner/Org Admin/Dept Manager/Team Lead/Member/Viewer; mandatory/default/optional policies, explicit override capability for default only. Admin/employee profile separate from sensitive personnel case file; work position, supervisor, status, verified work contacts, documents with granular grants and access audit. Employee disciplinary/corrective records privacy and retention distinct from public kudos. Basic availability, resource/equipment allocation, and optional capacity checks; **no full HR/payroll**.

Corporate finance: shared Expense proposals, receipt and payer metadata, categorization/department/project link, versioned review/approve/reject, exact budget allocation, commitments, member reimbursement request and separate acknowledged settlement. Company/department/project budget and variance. No automatic personal ledger mutation; personal paid expenses recorded via explicit, idempotent owner action. Do not claim accounting-grade general ledger/tax/invoicing support. Approval engine versioned with transitions, assigned reviewer, escalation/rejection/history and relevant grant checks. Reports permitted KPI, portfolio, capacity, expense and budget; private knowledge base folder/file versions/search; authorized scoped exports and audit. Transfer Owner through membership/acceptance/reauth/succession without legal transfer, archive/restoration with retention.

**Acceptance examples:** Company Admin cannot see sealed employee files absent grant; dept override cannot disable mandatory security; cross-company project data never leaks; expense not counted before approval; reimbursement cannot be marked paid merely by request; owner transfer succeeds only on acceptance and leaves >=1 eligible custodian; downgrade not delete data.

## Phase 5 — Communication & Meetings
One conversation engine independent of company so friends can DM without work affiliation. Direct conversations, private groups, and explicitly scoped work channels. Conversation participants and Membership tracked separately; revocation effective immediately across send/list/history/download/realtime. PostgreSQL committed messages with stable per-conversation order and idempotent client operation IDs, edits/history, durable outbox. REST history, authorized WebSocket adapter with replay/cursor bound to membership and backpressure; distinct presence/typing ephemeral data. Message content bounded rich text, safe link previews only if explicitly authorized, images and file attachments, voice <=2min <=10MB with private StoragePort and verified MIME/content. Reply/thread parent in same authorized conversation, reactions, mention privacy, pin/forward only when target authorized, search only across visible histories.

DM Block disallows direct messaging/contact and suppresses blockee presence and direct mentions; shared Group messages may still be visible; optional local collapse, moderation and member removal are separate. Message sent/delivered/read semantics and privacy settings per context; edit <=48h, normal author delete-for-everyone allowed in DM and private groups within 48h, and in work channels within 48h only if current authorized organization/channel policy allows, delete-for-self thereafter any time without affecting others; retained history and legal constraints explicit. Private group history from member join by default, work-channel history as authorized policy. DM and workplace retention differ, versioned/recorded, exact days to be approved prior to implementation. Deleted-account author display anonymized when required but allowed messages remain coherent.

Meetings independent/personal or bound to Project/Team/Company; invitation/RSVP, agenda, minutes draft/review/approval/final, decisions, action items linking authoritative task, attached files and external meeting URL. Bulletin/Announcement scopes, publication, pin, optional acknowledgement. Meeting integrations to Meet/Teams/Zoom APIs deferred; **no native live voice/video or v1 E2EE**.

**Acceptance examples:** blocked user DM rejected but common group read remains per group permissions; newly joined member can't page before join; company admin cannot search unrelated DM; session revoked while WebSocket connected evicts stream; unauthorized file read fails; non-replayed message send; 48h author edit and after-window delete-for-self; comment vs message history distinction; deleted user left readable pseudonymized thread.

## Phase 6 — Social
Connections are mutual-acceptance independent from team/group membership; email or verified phone lookup privacy-preserving and abuse-limited. Circle is a private classification, not a tenant/membership. Social Group distinct from work Team with Owner/Admin/Member; private default; optional discoverable preview but mandatory approve-to-join; no anonymous write. Activity independent/group-owned with templates, multi-day travel schedules, RSVP/capacity/waitlist, consent-based Free/Busy, polling, shared authorized Tasks/Calendar/Chat/Files, reminders and agenda.

Shared expenses: any verified, authorized member/participant of the Group or independent Activity may submit a proposed item, authorized approver must explicitly approve or edit; until then NOT counted; correction to approved record is Pending while current effective version remains. Equal/fixed/percent/weighted splits with exact remainder; each member sees their share/paid/owed; narrow aggregate permissions; settlement request and confirmation only, not actual money movement. Owner-approved optional write to Personal Finance, idempotent, no automatic reversal of personal posting after shared edit.

Lending/Lost & Found: personal or group property, evidence of borrower acknowledgement, request/hand-over/return with timestamps; an item may be reported missing, and another member may indicate found/held; resolution requires confirmation and conflict state; overdue/disputed/lost/damaged documented, no financial fine automation. Private albums with max original image 20MB, safe generated thumbs and workspace storage quota configured in future Admin; controlled media access/lifecycle. Opt-in social goals/challenges; no automatic private habit disclosure. Departure retains only necessary history/financial allocations/other participant rights, revokes access and handles custody.

**Acceptance examples:** discoverability doesn't expose private membership; join request can't read chats before approval; invoice draft doesn't affect totals; correction doesn't silently alter settled balance; exchange of found property requires acknowledgement; shared asset doesn't reveal owner's private home address; album file cap/quotas enforced once entitled and media only accessible via authorized context.

## Phase 7 — Platform Administration and commercial controls
Separate admin routes/authn authorization; Super Admin, Support, Billing Manager, Security Reviewer with MFA, sensitive-action reauth and audit. User/Workspace metadata, verification/suspension, counts/usage, safe abuse/support cases, without broad reading of private content. Central catalog of features with stable keys, release flags, entitlement rights, quota definitions and usage owner. CRUD/admin transitions for versioned Plans, fixed per-Workspace tier pricing with member cap, ownership of user vs company/team allowance, grant exceptions, trials/promos, add-on capability and scheduled activation. Percentage/segment feature flags with rollback. Workspace plan change and over-limit handling preserve records and authorized read/export; restrict creation/growth, never block account deletion or legal export.

Commercial activation is **not** automatic in Phase 7. All available features free and paid plan restrictions disabled until owner explicitly authorizes paid launch. Manual plan assignment and simulations should work; eventual provider checkout/invoice/payment/refund require separately reviewed financial/provider/compliance specification and operational gate. Aggregate metrics, growth, storage and runtime monitoring, audited admin operations. Future plans may make 2 owned active personal projects a Free tier cap, extra Companies payable, Company/Team a fixed-price Workspace + member ceiling, but no prices/caps or active charges until explicitly approved.

**Acceptance examples:** an Admin cannot inspect private journal/message on role alone; plan edits are versioned and not retroactively destructive; future 2-project owned cap never counts membership in other's project; provider connection disabled by default; grant expiry/revocation atomic and audited; account closed during admin action denies stale access; quota race cannot bypass enforced limits once paid gate approved.

## Integration-contract requirements for every phase (not frontend implementation)
- Publish validated **machine-readable OpenAPI 3.x JSON**, with deterministic source/version, complete actual operation set, Zod request/response parity, consistent auth/cookie/CSRF/CORS/error/idempotency/revision/timezone examples, and an update for each accepted batch. Report actual Swagger UI/JSON URLs only after verifying actual runtime configuration.
- Do not invent future endpoints in an exported contract. Proposed API routes must be kept separate from generated currently implemented OpenAPI. Frontend Agent consumes the stable documented contract; no frontend implementation in this package.
- Phase 2 explicitly needs controlled member invitation AND limited resource collaborator access; collaborators must be verified registered users, not anonymous edit-link guests. Invitation acceptance, owner succession and project-resource sharing are separate flows.
- Backend must offer authorized per-source calendar overlays: filtering combinations of Personal/Project/Team/Company/Social sources; Busy/Free and permission-safe metadata; no inferred exposure of private event titles. A user-accepted Task appears automatically as a **view projection**; private TimeBlock creation uses user preference.
- In Phase 3 work metrics never become automatic punishment or hidden rankings; recognition/corrective actions are domain records with appeal and approved bounded visibility, not personal gamification XP.
- In Phase 5 the author-edit limit is approved as 48h, and after 48h ordinary author deletion is self-only. Delete-for-everyone during the initial 48h is APPROVED for DM and private groups; in work channels it is allowed only by the authorized organization/channel policy. After 48h ordinary author deletion is self-only. Required retention/moderation/legal exceptions remain separate. Exact per-context retention duration remains a policy decision before executing the affected batch.
- In Phase 6 verify independent-Activity-only expense submission; all members/participants can submit proposed expense but only an authorized approver makes it effective. Social photos are approved for Phase 6 with **20MB per original** and future centrally adjustable workspace quota, but codec/security/storage sizing needs implementation approval.
