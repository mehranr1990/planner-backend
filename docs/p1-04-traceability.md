# P1-04 requirements traceability

Binding sources: MP-IMP-001 §§3.1–3.3, 4/P1-04, 5–8; MP-ENG-001; approved ADRs
0008, 0009 and [0010](adr/0010-calendar-temporal-semantics.md).

| Requirement                                                                      | Route/entity or implementation                                                                  | Verification                                                                                                        |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Separate event lifecycle, revision CRUD and retained deletion                    | `/calendar/events`, `/events/{id}`; CalendarEvent                                               | calendar integration: creation/read/update/cancel/tombstone, stale concurrent edit                                  |
| All-day exclusive end, date/instant separation                                   | Schedule union; DATE vs TIMESTAMPTZ checks                                                      | calendar domain/contracts and integration all-day/leap boundary                                                     |
| Timed IANA zones, explicit gap rejection, earlier fold                           | normalizeSchedule/wallInstant; saved wall/UTC context and returned policies                     | calendar domain DST/midnight/Apia/travel; integration gap/fold                                                      |
| Supported recurrence patterns, exclusions and gap results                        | EventRecurrence definitions; bounded pure expansion                                             | expansion domain: rule matrix, month-end, leap dates, gap/fold, exclusions                                          |
| Stable occurrence identities and explicit exceptions                             | CalendarEvent `(seriesId, recurrenceKey)` unique; series edit API                               | integration moved/canceled exception, concurrency, SQL uniqueness                                                   |
| Historical consistency and three edit scopes                                     | typed immutable recurrence versions, key boundaries, linked split                               | expansion historical-version and cancellation tests; integration ENTIRE_SERIES/split/terminal history/replay        |
| Time Blocks with optional existing Tasks, no Task/My Day duplication or mutation | `/calendar/time-blocks`, `/{id}`; scoped Task FK and public PlanningTasks read contract         | integration Task/history/date/My Day preservation, completed/deleted/master/skipped references, stale/foreign links |

| Personal authorization and nested ownership                                      | verified guard, personal scope, scoped repositories/FKs                                         | integration all routes, swaps/nested IDs, filters, views, conflicts, direct SQL FK denial                           |
| Concurrency/idempotency/retry                                                    | scoped DB locks, If-Match, unique exception/successor/current-version, actor-bound 24h receipts | integration concurrent create/edits/exception, event/block retries and split replay; compiled smoke restart receipt |
| Safe audit/outbox and errors                                                     | same-transaction metadata audit/events; strict Zod and safe envelopes                           | integration audit/outbox privacy, failure/duplicate consequences; earlier platform gates                            |
| Additive migration/data preservation                                             | two P1-04 migrations, no old/provider edits                                                     | migration safety, empty replay, P1-03 upgrade row snapshots, repeat deploy; eight checksum checks in both DBs       |
| Existing API compatibility and earlier batches                                   | P1-03 signature baseline plus all earlier baselines                                             | openapi:check, calendar OpenAPI contract tests and full prior unit/integration gates                                |
| Real compiled API and restart persistence                                        | `pnpm smoke:p1-04`                                                                              | events/blocks, all-day/DST, exception/split receipt, Task/My Day, conflicts, ownership, timezone and tombstone      |
