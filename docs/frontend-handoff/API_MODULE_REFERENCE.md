## Reading the operation tables

Each operation ID links to its exact OpenAPI JSON Pointer. The complete request schema is under that operation's `requestBody.content[mediaType].schema`, parameter schemas under `parameters`, and response schemas under `responses[status].content[mediaType].schema`. Follow `$ref` into `components.schemas` when present. Most domain schemas are intentionally inline; no invented named DTO is implied. The compact body column lists top-level fields only; `*` means required at the boundary. Nested schemas, enums, defaults, bounds, unions and error bodies remain in the JSON rather than being duplicated here.

`Q` = query, `H` = header; `!` = required header/query. Path UUID/date keys appear in the URL and are required. `none` means no documented request body; where a controller accepts an optional empty body use only `{}`. Check the schema before adding query parameters: unrecognized fields are rejected. Mutation Origin is enforced globally even where an individual operation does not repeat the parameter. Cookie/verification and capability exceptions are explained in the [guide](./FRONTEND_INTEGRATION_GUIDE.md) and [security handoff](./FRONTEND_SECURITY_AND_FILES.md).

Success/error columns show documented statuses and response media types; universal parser, rate-limit and unexpected-failure responses can occur in addition. Do not parse a 204 response as JSON. JSON responses use the linked schema, binary/CSV downloads use streams.

## Shared request behavior

- Business paths include `/api/v1`; health paths do not. Do not add that prefix twice.
- Standard scoped cursor lists use string `limit` 1–100 (normally default 25), opaque `cursor`, and `{items,nextCursor}`. Calendar/finance/search/sync have their own bounded cursors; follow the exact operation schema, including empty pages with a continuation cursor.
- Task lists whitelist status/priority/parent/root/label/scheduled/due/deleted predicates. No general-purpose arbitrary sort/filter API exists. Notes/folders/categories/routines expose explicit position semantics; other owner lists/history retain their documented stable ordering.
- Entity mutations normally use a quoted ETag in `If-Match`. Nested ownership matters: checklist operations use Task revision, Goal child operations use Goal revision; planning selections use Day revision plus source Task revision. Settings If-Match is optional for compatibility but recommended.
- Idempotency headers are per-operation in the tables. Most online receipts last 24 hours; sync has a separate permanent minimal replay identity and 30-day response-body policy.
- HTTP errors use `{error:{code,message,requestId,details?}}`. The exception filter emits generic stable status codes (400 BAD_REQUEST/VALIDATION_ERROR, 401 UNAUTHORIZED, 403 FORBIDDEN, 404 NOT_FOUND, 409 CONFLICT, 413 PAYLOAD_TOO_LARGE, 415 UNSUPPORTED_MEDIA_TYPE, 429 RATE_LIMITED, 503 SERVICE_UNAVAILABLE, otherwise INTERNAL_ERROR). Do not expect internal exception labels to survive as top-level codes. Bulk/sync per-item errors are typed response data.
- Dates are Gregorian ISO strings, instants UTC, IANA zones explicit, money exact decimal strings. See [types/state](./FRONTEND_TYPES_AND_STATE.md) for temporal and currency exceptions.

## Contract ownership and integration boundaries

`writing` groups Notes, Journal/Mood, Capture, personal search and dedicated voice storage, which remain distinct backend owners. `focus` includes the dedicated Task productivity facade; Task identity remains in Tasks. `account` includes the Personal Space lookup, not a membership API. `personal-lifecycle` is the staged export/deletion coordinator.

There is no public audit, outbox, queue-administration, raw file-volume, Swagger UI or runtime OpenAPI JSON endpoint. There are no Project/Team/Company/Friend/Chat APIs. Treat [future architecture](../architecture/FUTURE_PLATFORM_ARCHITECTURE.md) as proposals only.
